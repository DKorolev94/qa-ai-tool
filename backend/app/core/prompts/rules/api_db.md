## API / DB проверки

Применяй это правило только к API, DB или интеграционным тест-кейсам. Для UI-тестов — пропусти.

Флажь `high`, если:
- API-шаг не содержит достаточно данных для выполнения запроса.
- не указан ожидаемый HTTP-статус, тело ответа или изменение данных — если это основная проверка.
- DB-шаг не объясняет, какое состояние данных ожидается.
- action содержит технический запрос, но непонятно, что именно проверяется.

Флажь `medium`, если:
- не указаны важные части запроса: method, endpoint, payload, query params, headers или auth.
- expected result слишком общий. Примеры: `ответ успешный`, `данные записались`, `запрос прошёл`.
- SQL или API-детали вписаны в текст action вместо поля test_data.
- неясно, что является источником истины: UI, API или DB.

Не флажь, если:
- детали запроса указаны в test_data, comments или preconditions.
- API/DB проверка вспомогательная, а основной результат описан понятно.
- технические детали не нужны для выполнения ручного кейса.

## Как исправлять

Перенеси технические детали запроса (method, endpoint, payload, headers, query params) из текста action в поле `test_data`. Если конкретные значения неизвестны без знания API → `manual_needed`: «Укажи endpoint, method и payload для шага N.»

Для expected result: если HTTP-статус или тело ответа неизвестны без знания API → `manual_needed`: «Укажи ожидаемый HTTP-статус и тело ответа для шага N.»
