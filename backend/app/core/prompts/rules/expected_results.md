## Ожидаемые результаты (Expected Results)

Expected result = наблюдаемое состояние системы после действия. Примеры: текст на экране, URL, HTTP-статус, сообщение об ошибке, наличие или отсутствие элемента, запись в БД.

Флажь `high`, если:
- expected result отсутствует у основной проверки тест-кейса.
- у большинства шагов (более половины) нет expected results — не только у финального. Тестировщик не знает, что проверять на промежуточных шагах.
- expected result невозможно проверить.
- непонятно, что именно должен увидеть тестировщик.

Флажь `medium`, если:
- expected result слишком общий. Примеры: `успешно`, `корректно`, `правильно`, `OK`, `ошибка`. Непонятно, что именно "успешно".
- expected result описывает действие, а не состояние системы. Пример плохо: `Нажать кнопку OK`. Пример хорошо: `Открывается страница /dashboard`.
- expected result есть, но недостаточно конкретен для проверки.

Не флажь, если:
- expected result краткий, но однозначно проверяемый.
- шаг является навигацией или setup и не имеет отдельного expected result. Если итоговая проверка понятна — не флажь.
- один expected result покрывает несколько связанных шагов и это очевидно из контекста.

## Как исправлять

Замени общее («Успешно», «Корректно») на конкретное состояние системы: URL, текст, статус, элемент, сообщение. Выводи из action и контекста шагов. Если конкретный результат неопределим без знания бизнес-логики → `manual_needed`: «Укажи expected result для шага N.»
