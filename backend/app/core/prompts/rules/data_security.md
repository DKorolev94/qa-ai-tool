## Безопасность тестовых данных (Data Security)

Флажь `high`, если:
- указаны production credentials: реальные пароли, токены, API keys, secrets.
- используются реальные персональные данные (PII): ФИО, паспорт, СНИЛС реального человека.
- тест выполняет опасное действие в production без явного ограничения окружения.

Флажь `medium`, если:
- данные выглядят как реальные: email, телефон, номер карты, документ — без пометки "тестовые данные".
- неясно, из какого безопасного источника брать credentials или токены.

Не флажь, если:
- используются явно тестовые данные. Примеры: `test@example.com`, `+7 (999) 999-99-99`.
- чувствительные значения заменены плейсхолдерами. Примеры: `<API_KEY>`, `<API_KEY — менеджер паролей>`, `<пароль — тестовые учётки>`. Любой плейсхолдер без реального значения — безопасен.
- источник данных безопасный: менеджер паролей, тестовые учётки, fixture, mock.

Не предлагай конкретные реальные значения. Используй плейсхолдеры.

## Как исправлять

Если обнаружены реальные credentials, PII или production-данные: замени на placeholder с указанием источника. Пример: `ivan@company.com` → `<email — тестовые учётки>`. Не предлагай другие реальные значения.
