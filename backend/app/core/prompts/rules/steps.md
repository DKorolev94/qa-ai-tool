## Шаги (Steps)

Флажь `high`, если:
- поле `action` у шага пустое или состоит только из пробелов. Шаг без действия невыполним.
- шаг использует объект или состояние, которое создаётся только в более позднем шаге. Пример: шаг 2 удаляет запись, которую создаёт шаг 5.
- порядок шагов логически невозможен.
- expected result не соответствует действию в action.

Флажь `medium`, если:
- один шаг содержит несколько независимых действий через запятую. Пример: `ввести email, ввести пароль, нажать кнопку`. Это три разных шага.
- шаг описывает расплывчатую цель без конкретного критерия. Примеры: `убедиться, что система работает`, `проверить корректность`. Непонятно, что именно проверять.
- пропущен важный переход или действие. Без него следующий шаг невозможен.

Флажь `low`, если:
- есть лишние технические шаги, не относящиеся к тесту. Примеры: `открыть браузер`, `ввести адрес сайта`.

Не флажь, если:
- действия физически нераздельны. Пример: `нажать и удерживать`. Это одна атомарная операция.
- шаг содержит конкретный observable критерий. Примеры: `Убедиться, что URL содержит /auth/login`, `Проверить статус ответа 200`. Это конкретная проверка, а не расплывчатая цель.
- требуемое состояние не описано в preconditions. Это нарушение правила `preconditions`, не `steps`.

Если флажишь «несколько действий в одном шаге»: в recommendation напиши: `Разбить шаг N на X шагов: [шаг 1], [шаг 2]...`. Данные из action перенести в test_data.

Если флажишь «расплывчатая цель»: в recommendation предложи конкретное переформулирование с observable критерием: элемент, текст, статус, URL. Не предлагай другую форму «убедиться, что...».

## Как исправлять

Если issue о нескольких действиях в одном шаге: раздели на отдельные шаги. Данные из action → test_data. Для каждого нового промежуточного шага добавь очевидный expected result из контекста действия:
- «ввести email» → «Поле email заполнено без ошибок»
- «ввести пароль» → «Поле пароль заполнено без ошибок»
- «нажать кнопку» → берётся из оригинального expected result исходного шага

Если issue о расплывчатой цели: переформулируй в конкретное действие с observable критерием (элемент, текст, URL, статус). Не предлагай форму «убедиться, что...». Если критерий неопределим из контекста → `manual_needed`: «Укажи observable критерий для шага N.»

Если issue о нарушении порядка шагов или пропущенном переходе → `manual_needed`.
